# 후속 개선 요구사항

작성일: 2026-09-20  
대상: ForgeFlow, `modeling_local_mcp`, `blender-control-mcp`, `blender-prompt-agent`, `unity_local_mcp`, `unity_mcp`

이 문서는 현재 구현과 E2E 검증 이후 남은 개선 항목을 정리한다. 남은 사용량과 작업 위험을 고려해 작은 변경으로 효과가 큰 항목부터 진행한다. 자동 검증으로 확인할 수 없는 모션의 자연스러움과 최종 화면 품질은 사용자 검토 항목으로 유지한다.

## 우선순위

| 우선순위 | 범위 | 목표 | 예상 규모 |
|---|---|---|---|
| P0 | Unity 카메라·구도 | 생성 직후 캐릭터가 화면에 적절한 크기로 보이게 함 | 작음~중간 |
| P0 | Bridge 버전 확인 | 구버전 Bridge 사용으로 인한 도구 실패를 사전에 차단 | 작음 |
| P1 | 애니메이션 검증 세분화 | 확인 가능한 조건과 사람 검토 조건을 분리 | 중간 |
| P1 | 결과 비교 UX | 이전 버전과 현재 결과를 쉽게 비교 | 중간 |
| P2 | 짧은 재생 영상 | 정지 화면만으로 알기 어려운 변형 문제를 확인 | 중간~큼 |
| P2 | Idle/Walk 전환 품질 | 게임용 상태 전환과 발 미끄러짐을 검사 | 큼 |

## P0-1. Unity 카메라 자동 맞춤

### 문제

실제 Play 스크린샷에서 캐릭터가 작게 보였다. 씬 배치와 Play 성공은 확인되지만, 사용자가 결과를 바로 보기에는 화면 활용도가 낮다.

### 요구사항

- Renderer 전체 bounds를 기준으로 캐릭터 중심과 높이를 계산한다.
- 카메라 시야각과 화면 비율을 사용해 캐릭터 높이가 화면의 60~75%가 되도록 거리를 계산한다.
- 좌우 폭이 화면 밖으로 나가지 않도록 높이와 폭 중 더 큰 제약을 사용한다.
- 카메라가 캐릭터의 앞쪽을 향하는지 확인하고, 전신 bounds가 화면 안에 들어오는지 재검사한다.
- 기존 카메라·조명 설정은 백업하고, 새로 만든 ForgeFlow 씬에서만 수정한다.
- 자동 맞춤 결과에 `cameraPosition`, `lookAt`, `distance`, `bounds`, `framingRatio`를 기록한다.

### 완료 조건

- 전신이 잘리지 않고 화면 높이 비율이 0.60~0.75 범위에 들어온다.
- 가로 폭이 화면 밖으로 나가지 않는다.
- 기존 사용자 씬을 수정하지 않는다.
- 단위 테스트에서 좁은 모델, 넓은 모델, 매우 큰 모델, 음수 좌표 모델을 각각 처리한다.
- 실제 Unity 씬에서 Play 전후 스크린샷을 비교한다.

## P0-2. Unity Bridge 버전·기능 확인

### 문제

ForgeFlow가 연결된 Editor의 Bridge가 애니메이션 도구를 지원하는지 연결 직후 알기 어렵다.

### 요구사항

- `unity_ping` 응답에 Bridge 버전, 지원 도구 목록, 프로젝트 경로를 포함한다.
- ForgeFlow가 요구하는 최소 Bridge 버전과 필수 도구를 선언한다.
- 버전이 낮거나 도구가 없으면 Unity 요청 전 화면에 원인과 설치 경로를 표시한다.
- 새 도구를 사용하지 않는 일반 요청은 호환 가능한 범위에서 계속 사용할 수 있다.
- 연결 시 소스 버전과 실제 설치된 Bridge의 SHA-256을 로그에 기록한다.

### 완료 조건

- 구버전 Bridge를 연결했을 때 애니메이션 프리셋이 비활성화된다.
- 최신 Bridge에서는 Avatar·Clip·Controller 도구가 준비 상태로 표시된다.
- 버전 불일치가 모델 실패 이후가 아니라 연결 단계에서 표시된다.

## P1-1. 애니메이션 검증 세분화

### 문제

현재 자동 검증은 Avatar, Clip, Controller, 재생 시간, 본 변화까지 확인하지만 모션의 의미와 시각적 자연스러움은 자동으로 확정하지 않는다. `verified`와 전체 요청 `partial`을 사용자가 혼동할 수 있다.

### 요구사항

자동 검증 항목을 다음처럼 분리한다.

1. **구조 검사**: Avatar가 유효한지, Clip·Controller GUID/localId가 현재 자산과 일치하는지 확인한다.
2. **재생 검사**: Play 중 frameCount, normalizedTime, clip weight, stateHash가 진행하는지 확인한다.
3. **변형 검사**: Hips와 주요 팔·다리 본의 local pose가 실제로 변하는지 확인한다.
4. **설정 검사**: clip length, loop, speed, default state, 전환 조건을 확인한다.
5. **사람 검토**: 동작 의미, 발 미끄러짐, 관절 꺾임, 자연스러움, 조명과 구도.

각 항목에 `measured`, `unmapped`, `failed`, `not_applicable` 중 하나를 기록한다. 사람 검토 항목이 남아 있으면 전체 결과는 자동으로 완료 처리하지 않는다.

### 완료 조건

- `requested_checks`와 `measured_checks`의 차이가 UI에 표시된다.
- `unmapped`가 있으면 결과 상태가 `partial`로 보인다.
- Clip이 연결되었지만 재생되지 않는 경우 구조 성공과 재생 실패가 분리된다.
- 기존 receipt와 호환된다.

## P1-2. 결과 비교 UX

### 요구사항

- 현재 버전과 직전 버전의 입력 경로, SHA-256, Avatar, Clip, Controller, 씬 경로를 나란히 보여준다.
- Blender 결과는 rest/pose 미리보기와 리깅 품질 요약을 비교한다.
- Unity 결과는 Play 스크린샷과 주요 본 샘플을 비교한다.
- 이전 결과를 현재 승인으로 오인하지 않도록 버전 라벨을 항상 표시한다.
- 비교 화면은 읽기 전용이며 원본 산출물을 수정하지 않는다.

### 완료 조건

- 새 리깅 또는 새 Unity 가져오기 후 이전 승인과 현재 검토 상태가 분리되어 보인다.
- 비교 대상이 없을 때 빈 상태 안내가 표시된다.
- 파일이 삭제되거나 경로가 바뀌어도 저장된 이력은 열 수 있다.

## P2-1. 짧은 재생 영상과 프레임 검사

### 요구사항

- 지정한 짧은 구간을 2~5초로 재생하고 일정 간격의 프레임을 캡처한다.
- 영상 생성 실패가 애니메이션 구조 성공을 덮어쓰지 않도록 별도 상태로 기록한다.
- 모든 프레임을 저장하지 않고 대표 프레임과 영상 파일만 변경 manifest에 포함한다.
- 영상은 사용자 검토용이며 자연스러움 자동 판정으로 표시하지 않는다.

### 완료 조건

- Play 중 생성된 영상에 최소 3개 이상의 서로 다른 프레임이 있다.
- 원본 FBX와 씬 파일은 변경되지 않는다.
- 취소 후에도 부분 영상과 로그가 진단 폴더에 남는다.

## P2-2. Idle/Walk 전환과 발 미끄러짐

### 요구사항

- Idle과 Walk Clip을 정확한 GUID/localId로 연결한다.
- 속도 파라미터와 전환 조건을 읽어 현재 Controller와 비교한다.
- 발 본의 지면 접촉 구간을 샘플링하고 이동량과 회전량을 기록한다.
- 자동 결과는 전환 설정과 발 이동 수치만 제공하며 자연스러운지 여부는 사람 검토로 남긴다.
- 외부 모션 생성 서비스는 기존 로컬 Clip 생성과 별도 경로로 취급한다.

### 완료 조건

- Idle→Walk→Idle 전환이 실제 Play에서 관찰된다.
- 전환 전후 stateHash와 clip identity가 일치한다.
- 발 미끄러짐 의심 구간이 수치와 프레임 번호로 표시된다.
- 전환 조건을 확인하지 못하면 `partial`로 남는다.

## 공통 비기능 요구사항

- 모든 단계는 입력 버전, SHA-256, 프로젝트 경로, 도구 버전, 실행 시간을 기록한다.
- 실패한 실행은 성공 결과로 재사용하지 않는다.
- 사용자 프로젝트 전체를 검색하거나 관련 없는 자산을 삭제하지 않는다.
- 모델 응답이 timeout되면 부분 tool call을 실행하지 않고 다음 요청을 새 deadline으로 시작한다.
- 기존 테스트와 이전 Job 스키마를 유지한다.
- Unity 실제 E2E에서는 모델이 작성한 산출물과 호스트가 측정한 결과를 별도로 기록한다.

## 권장 진행 순서

1. P0-1 카메라 자동 맞춤과 P0-2 Bridge 버전 확인을 구현한다.
2. P1-1 애니메이션 검증 상태를 UI와 receipt에 연결한다.
3. P1-2 결과 비교 화면을 추가한다.
4. 충분한 검증 여유가 생긴 뒤 P2의 영상과 Idle/Walk 전환을 진행한다.

## 현재 제외 범위

새 이미지 생성 모델 교체, 자동 리토폴로지, 완전한 IK/FK 편집기, 고품질 걷기 모션 생성, 영화 수준의 조명·카메라 자동 연출은 이 요구사항의 범위를 넘어선다.
