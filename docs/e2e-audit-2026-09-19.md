### 2. [P2] Unity Agent 종료 후 Turn과 단계가 running에 남음

- 재현: 실행 중인 Turn이 있을 때 완료 이벤트 없이 프로세스가 exit 0으로 종료하거나, `session_error`를 받은 후 exit 1로 종료한다.
- 실제 상태: 세션은 `closed` 또는 `failed`지만 Turn과 Unity 단계는 `running`, `_active_turn`도 유지된다. 일반적인 exit 1 대조군은 정상적으로 `failed`가 된다.
- 영향: 이미 끝난 작업이 계속 실행 중으로 보이고 E2E의 Turn 대기가 제한 시간까지 지속될 수 있다.
- 근거: 프로세스의 종료 코드와 세션 상태를 통제한 격리 재현. 실제 라이브 프로세스에서 같은 종료 조건을 강제하지는 않았다.
- 코드: `src/forgeflow/adapters/unity_adapter.py:594`, `:620`.
- 증거: `logs/e2e-audit-20260919/unity-exit-repro.json`.
- 개선: 세션 종료 코드와 무관하게 미완료 Turn을 정리한다. 명시적 취소는 cancelled, 예상하지 못한 종료는 failed로 저장하고 화면 갱신 신호를 보낸다.

## E2E 검증 도구 자체의 개선점

1. **실패 증거와 Job 상태를 항상 저장**: `run_full_e2e.py:41`에서 산출물 수집 예외를 주입했을 때 단계는 `running`, 오류는 null, evidence 파일은 미생성 상태였다. `try/except/finally`에서 실패 상태와 부분 증거를 기록해야 한다. 증거: `full-failure-repro.json`.
2. **성공 판정 강화**: `run_unity_e2e.py:159`는 Turn 성공과 인간 검토 pending만 검사한다. 저장한 `automated_status`가 failed/partial/unavailable이어도 프로세스 종료 코드만 보면 성공할 수 있다. 명령 실행 성공과 결과 검증 성공을 별도로 집계해야 한다.
3. **저장된 설정 사용**: `run_rigging_e2e.py:107`은 `AppConfig.load()` 대신 기본 설정으로 생성하므로 사용자 엔진 경로·모델 설정과 실제 앱 환경이 달라질 수 있다. 작업 루트만 재정의하는 방법이 적절하다.
4. **전체 경로 통합**: `run_full_e2e.py`의 실제 범위는 이미지→Blender다. 리깅·Unity·UI까지 포함한 전체 결과 매니페스트가 필요하다. 이번 점검은 후속 리깅을 실제 앱 `PipelineService.start_rigging`으로 연결했다.
5. **결과 의미 검증**: smooth shading 명령 실행과 파일 수집 외에 실제 polygon shading 상태를 검증하면 무효 편집을 잡을 수 있다.

## 검증 한계

- 회귀 테스트는 외부 엔진 실패 경로 전체를 보장하지 않는다. 실제 엔진 실행과 격리 장애 재현 결과를 구분했다.
- UI smoke는 Qt offscreen 위젯 조작이며 파일 선택·작업명 대화상자 응답은 대체했다. Windows 네이티브 대화상자의 직접 조작 E2E는 아니다.
- 초기 sandbox Python/Unity 실행 실패는 권한 경계에 따른 검사 환경 문제로 분류했다.
- 기존 사용자 작업과 앱 설정은 테스트 대상으로 사용하지 않았으며, 별도 테스트 Job과 임시 Unity 프로젝트를 사용했다.
